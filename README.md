# PartyTargetWatch · 队友目标

独立的《魔兽世界》正式服插件，用一个可移动窗口显示自己及小队、团队成员**当前选中的目标**。界面与命令提示为简体中文。

当前版本：`0.4.0`，面向正式服 `12.1.0`，TOC 接口版本 `120100`。本版支持从公开聊天声明中提取怪物名称；用户已确认 `%f` 展开及插件接收，并在修正后确认标记图标与纯怪物名称正常显示。CurseForge 资料处于准备状态，尚未提交或发布。

## 功能

- 每行显示“成员 → 当前目标”；离线成员显示“离线”。
- 显示目标的团队标记。
- 单人时显示自己，小队最多 5 人，团队最多 40 人；超过 20 人时分两列。
- 大约每 0.2 秒刷新可见窗口；响应换目标、组队和成员连接等事件。
- 拖动窗口标题调整位置，点击“锁定”固定位置。
- 点击“设置”调整 60%–200% 整体大小、X/Y 位置偏移，以及显示、隐藏、锁定、居中、恢复默认。
- 背景不透明度可设为 `0`–`1`，默认 `0.88`；`0` 时背景、边框与行底色全透明，文字和图标保持可见。
- 点击“预览”显示 5 行示例数据，方便在未组队时调整布局。
- 按野外、主城/旅店休息区、地下城（含大秘境）、团队副本、场景战役、战场与竞技场选择显示；副本类型优先，预览忽略场景筛选。
- 可选焦点列、公开焦点共享和严格聊天声明记录，三个开关独立且默认关闭。
- 可编辑最多 20 条聊天声明识别模板，提取名称、标记或两者，并用样本文字测试草稿，无需发送聊天。
- 位置、大小、锁定与显示状态存储在 `PartyTargetWatchDB`，重载界面后保留；预览状态不保存。

窗口展示游戏 API 当时允许显示的目标信息。“无目标 / 不可见”可能表示没有选择目标，也可能表示该目标暂时不可查询。选中目标本身不能证明成员正在攻击、治疗或施法。插件在启用共享后可发送公开焦点的插件消息；不会向普通聊天发送目标通报，也不会自动选择目标或执行战斗操作。

0.3.1 已删除目标通报按钮、成员行点击通报、相关命令、快捷键和专用诊断，0.4.0 不恢复这些发送功能。目标名称受保护时，插件不能将它读取后发送到聊天；脱战不保证解除限制。玩家可手动使用游戏原生宏发送声明，本插件只识别已经发出且允许读取的消息。

## 焦点与聊天约定

在 `/ptw settings` 中按需启用：

| 开关 | 用途 |
| --- | --- |
| 显示队友焦点列 | 只控制列的可见性；默认关闭 |
| 启用焦点共享 | 默认关闭。双方均需安装并启用；各自只发送公开可读的自身焦点 |
| 记录聊天中的打断声明 | 默认关闭。独立于焦点共享，记录当前组员明确发出的约定 |

隐藏列、隐藏窗口或场景筛选不会关闭共享或声明记录；停止这两项功能需取消对应开关。自己的焦点在可读时直接显示；其他人的自动共享快照每 4 秒保活，12 秒未更新即过期，离组清除，不写入 SavedVariables。

声明只接受小队、团队和副本队伍聊天中与模板匹配的**完整消息**。声明者无需安装插件，接收方需启用声明记录。`取消打断` 始终作为固定取消语句清除本人声明。

从 `/ptw settings` 点击“通报格式…”或输入 `/ptw formats` 打开多行编辑器。这里配置的是**接收聊天时的声明识别格式**，不会生成或发送通报。默认模板为：

```text
我打断%mark
我的焦点打断是 {rt%mark}
PTW焦点：%name
```

- 每行一个模板，最多 20 个有效模板；每条最多 255 字节，总输入最多 8192 字节。编辑器忽略空白行，并去除每行两端的空格和制表符。
- 每条至少包含 `%mark` 或 `%name` 之一，二者各最多一个，另可有最多两个 `%text`。`%mark` 接受八种中文标记名、数字 `1`–`8` 或 `{rt1}`–`{rt8}`；写成 `{rt%mark}` 时匹配完整的 `{rtN}` 标记文字。
- `%name` 提取非空名称，清理后最多 96 字节。名称以 `{rt1}`–`{rt8}` 开头时，将该前缀显示为标记图标，剩余文字作为名称；它与显式 `%mark` 不一致时拒绝声明。只有名称而没有标记的模板必须含固定文字，例如 `PTW焦点：%name`，不能只有 `%name`。名称里的未展开 `%f`、`%t` 不作为怪物名接受。
- `%text` 匹配一段非空文字；`%name` 与 `%text` 之间必须有固定分隔文字，不能紧挨着。其他内容按字面匹配，包括标点和竖线；不作为 Lua 模式或代码执行。未知命名占位符会被拒绝。
- 按有效模板的顺序匹配；同一模板若能将一条消息解释成不同名称或标记，则拒绝这条消息。没有占位符的位置不能任意增加前后文。
- 样本测试使用当前草稿，不发送聊天，也不记录声明。点击“保存”才使新模板生效并清空旧声明；保存后的模板会保留至下次登录或 `/reload`。
- 保存空列表会停止识别新的声明；启用记录时，固定语句 `取消打断` 仍有效。关闭编辑器而未保存，不改变当前模板。

升级时保留你已保存的格式。打开 `/ptw formats`，点击“加入名称格式”，再点击“保存格式”，可将 `PTW焦点：%name` 加入列表；该按钮只修改编辑草稿，不会立即覆盖保存配置。

### 复用 SeUI 的快速焦点喊话

使用 SeUI 1.8.4 的队友可在“快速焦点”的喊话内容中填写：

```text
我的焦点打断是 {rt%mark} %f
```

接收方在 `/ptw formats` 中新增以下一行并保存，保留其他需要的模板：

```text
我的焦点打断是 {rt%mark} %name
```

每名队友只需配置自己的 SeUI 一次，之后用 SeUI 原来的点击或快捷键设置焦点，同一次操作会附带队伍喊话，无需另打字或另按通报键。接收方需开启焦点列和声明记录；发送方无需安装 PartyTargetWatch。SeUI 中保留“焦点时小队喊话”勾选，并选择一个非“无”的标记；战斗中修改设置要等脱战才应用。

`PTW焦点：` 只是示例前缀，用户可自定义整句文字；发送格式中的 `%f` 对应接收模板中的 `%name`。也可搭配使用 SeUI 的 `PTW焦点：%f` 与接收模板 `PTW焦点：%name`。

本机 SeUI 1.8.4 源码确认其先执行原生设置焦点，再执行配置的 `/p` 喊话，替换 `%mark` 并保留 `%f`。用户随后确认以上自定义格式联动成功。其中 `%mark` 是设置面板选择的标记；勾选“不覆盖已有标记”时，它可能与怪物已有标记不同。若名称同时带有不同的前置标记，PartyTargetWatch 会拒绝矛盾声明；不需要显式声明标记时可使用名称格式。这次本机验证不代表所有第三方通报插件均支持 `%f`，也未覆盖跨客户端、战斗与大秘境完整流程。

其他插件也可按同样思路配置：先确认它发到小队、团队或副本队伍频道的完整消息包含实际焦点名称，再把该名称所在位置写成接收模板的 `%name`，标记位置可用 `%mark`。发送插件可能使用自己的名称占位符，不能把“可自定义文字”等同于支持 `%f`；如果实际发出的是字面 `%f`，需要查该插件的占位符说明。只有打断成功时报告受击目标的消息，不能证明那是发言者的焦点，不应将这类模板用于焦点声明记录。消息本身受保护时仍不能解析。

### 用原生宏发送焦点名称

在游戏宏界面创建以下宏，由玩家自己按下：

```text
/stopmacro [@focus,noexists]
/p PTW焦点：%f
```

这段宏不改变当前目标。接收方开启“显示队友焦点列”和“记录聊天中的打断声明”，保存 `PTW焦点：%name` 后，就可尝试从 `PTW焦点：光耀播法者` 这样的公开消息中显示 **光耀播法者**。发送方无需安装插件；每名队友需自行发送自己的声明。不要把宏里的 `%f` 写进识别模板：宏用 `%f`，插件模板用 `%name`。

声明携带名称时，焦点列用黄色显示该名称；只有标记时继续显示黄色“约定：三角”等文字。名称来自发言者的声明，不能证明其此刻仍以该怪物为焦点，也不能区分同名的不同怪物。声明有效期 300 秒，离组、换场景或关闭记录时清除；可读的自动焦点优先。聊天锁定时自动缓存隐藏，已有公开声明可保留到过期。

只有标记的声明显示对应标记，不能可靠地换算为怪物名称：游戏可将附近单位的标记编号作为受保护值返回，插件无法用它做匹配。目标列通过已有单位直接显示名称是另一条显示路径，不代表能从一个标记反查名称。

原生宏能发出消息，不保证插件当时能读取消息。聊天正文或发言者受保护时，插件会忽略该消息；大秘境等限制可能覆盖整段活动。用户已确认本机 `%f` 展开及插件接收，修正后标记图标与纯怪物名称均正常显示；跨客户端、完整两行宏、战斗和大秘境中的完整流程仍未验证。插件不解读或发送秘密值，不使用外部通信桥接。接口依据与限制见源码仓库的 [API 核查记录](https://github.com/hiltay/PartyTargetWatch/blob/main/docs/API-NOTES.md)。

## 安装与更新

### 从 ZIP 安装

1. 退出游戏，打开对应正式服客户端的 `Interface/AddOns` 文件夹。
2. 解压发行包，将其中的 `PartyTargetWatch` 文件夹放入 `AddOns`。
3. 确认文件结构是 `Interface/AddOns/PartyTargetWatch/PartyTargetWatch.toc`，避免多套一层文件夹。
4. 启动游戏，在角色选择界面的插件列表启用 `PartyTargetWatch`。
5. 进入游戏输入 `/ptw` 显示窗口，或输入 `/ptw settings` 打开设置。

从旧版更新时，先将现有 `PartyTargetWatch` 文件夹备份到 `AddOns` 之外，再用新包中的完整文件夹替换，确保旧版 `Bindings.xml` 不再留在安装目录。游戏的 SavedVariables 位于 `WTF` 下；保留这些文件即可保留插件设置。

### 从本地仓库安装

工具需要 Python 3.10 或更高版本，仅使用标准库。在仓库根目录运行，**将示例路径替换为实际客户端路径**：

```powershell
python tools/install.py --addons-dir "D:\World of Warcraft\_retail_\Interface\AddOns"
```

安装器要求显式提供已存在的 `Interface/AddOns` 目录，只更新其中的 `PartyTargetWatch` 子目录。已有安装会先完整备份到仓库内的 `local-backups/`，并校验备份文件 SHA256；随后写入发布文件并移除已废弃的 `Bindings.xml`，其他遗留文件保留。它不修改 `WTF` 或 SavedVariables。

安装器拒绝符号链接、Windows 目录联接等重解析点，以及待覆盖的硬链接文件。安装前后会读取其他插件文件计算 SHA256，确认路径清单与内容未变；结果记录在已被 Git 忽略的 `validation/local-install.json`。校验失败时以非零退出码结束，报告可用于检查原因。请在安装期间关闭游戏与插件更新器，避免同时改动文件。若文件写入中途失败，已有安装的备份会保留；脚本不会自动回滚。

## 命令

`/partytargetwatch` 与 `/ptw` 等价。

| 命令 | 效果 |
| --- | --- |
| `/ptw` 或 `/ptw show` | 显示实时窗口，并结束预览 |
| `/ptw hide` | 隐藏监控窗口 |
| `/ptw settings` 或 `/ptw config` | 打开设置窗口 |
| `/ptw formats` | 打开多行声明格式编辑器与草稿测试 |
| `/ptw unlock` | 解锁拖动并显示窗口 |
| `/ptw lock` | 锁定位置并显示窗口 |
| `/ptw test` | 开启或结束示例预览，并显示窗口 |
| `/ptw scale 1` | 设置整体缩放；有效范围为 `0.6` 到 `2` |
| `/ptw reset` | 恢复本插件默认设置，包括不透明度、声明格式与三个默认关闭开关；结束预览 |
| `/ptw help` | 输出命令帮助 |

设置窗口的位置输入使用当前锚点的偏移量：X 正值向右，Y 正值向上。点击“窗口居中”可将锚点与偏移重置到屏幕中心。设置窗口可拖动，按 Esc 关闭。

## 本地开发与打包

```text
PartyTargetWatch/          游戏加载的 Lua 与 TOC
tools/package.py          校验 TOC 并生成发行 ZIP
tools/install.py          显式目标路径的本地安装器
README.md
LICENSE
CHANGELOG.md
```

在仓库根目录运行：

```powershell
python tools/package.py
```

生成 `dist/PartyTargetWatch-0.4.0.zip`，版本号来自 TOC。脚本校验 TOC 所列 Lua 文件。ZIP 只有一个 `PartyTargetWatch/` 顶层目录，内含 TOC、主 Lua、`Communication.lua`、`Settings.lua`、README、MIT 许可证和更新记录，共 7 个文件；不再包含快捷键文件。开发工具、测试依赖、本地备份、安装报告与 Git 数据不进入发行包。生成后会重新读取 ZIP 校验清单及内容，并输出 SHA256。

Git 用于保留源码与文档历史。`dist/`、`local-backups/`、测试依赖和本地安装报告均已忽略；提交前用 `git status` 和 `git diff --staged` 检查内容。发布时应核对 TOC 版本、更新记录、发行包内容及已验证范围。

## 验证范围

`0.4.0` 有 76 个 Lua mock 场景通过（39 UI、37 通信），交付测试 7 通过、1 因 Windows 符号链接权限跳过。用户已现场确认原生 `%f` 展开，并确认 0.4.0 接收、显示了名称；截图同时暴露前置 `{rt4}` 被错误显示成名称里的 `rt4`。本版增加前置标记提取后，用户第二轮确认“已正常显示图标和名字”，多余 `rt4` 文字已消失。跨客户端通信、完整两行宏、战斗与大秘境效果未验证，安装文件更新不等于这些场景已通过。`0.3.1` 的历史结果为 64 个 Lua mock（36 UI、28 通信）及交付测试 7 通过、1 因 Windows 符号链接权限跳过。

用户在追随者地下城脱战后反馈 0.3.0 的“目标信息受保护”提示，这说明当时主动通报路径无法使用目标信息，不证明所有队伍聊天都不可读。0.3.0 的历史离线记录为 69 个 Lua mock（37 UI、32 通信）及交付测试 7 通过、1 因 Windows 符号链接权限跳过；0.2.0 为 41 个 Lua mock（24 UI、17 通信）及相同交付结果。

历史 `0.1.0` 于 2026-09-25 实测过 `/reload` 加载、打开设置、切换预览、100% → 110% → 100% 缩放和自身目标名称更新。多人、团本、战斗与游戏内设置持久化当时未验证；这份历史记录不代表后续版本已通过实机验收，也不代表完全无 Lua 错误。

离线测试可以检查 Lua 语法、模拟 API 下的命令和布局逻辑，以及发行包结构；这些结果不能替代游戏客户端内的加载与战斗验证。

Lua 行为测试使用 Lua 5.1，运行方式：

```powershell
python -m pip install -r requirements-dev.txt
python tests/run_tests.py
```

也可将依赖安装到仓库内隔离目录：`python -m pip install --target .test-deps -r requirements-dev.txt`。测试运行器会自动识别该目录。源码仓库的 `validation/TESTING.md` 包含详细验证记录，发行 ZIP 不包含开发测试文件。

交付工具的标准库测试命令如下。测试仅创建临时的虚构仓库与 `Interface/AddOns`，不使用真实游戏目录：

```powershell
python tests/test_delivery.py
```

建议每次发布前在对应客户端确认：

- 单人、小队与团队增减成员时，名单和列数正确；离线、无目标与更换目标时显示合理。
- 战斗内外、切换地图后没有 Lua 错误，受限制的信息能按客户端允许的方式显示。
- 拖动、锁定、缩放、隐藏、预览及设置窗口正常；`/reload` 后已保存设置仍然有效。
- 40 人团队布局可读，窗口处于屏幕范围内。
- 两个客户端核验公开焦点共享、关闭/离组/超时清理、严格聊天声明和“约定”标识；在大秘境等限制开始与解除时不显示旧自动焦点。
- 标记设置/取消与场景切换正常；不存在目标通报按钮或快捷键，点击成员行不发送消息。
- 多行编辑器的长文本、光标滚动、中文输入、竖线、保存/取消、草稿测试、空列表和重载持久化正确；背景不透明度 `0`、`0.88`、`1` 不影响文字与图标。
- 分别验证 `%name` 名称声明、名称加标记及旧标记模板；检查“加入名称格式”只修改草稿，保存后收到原生宏消息能显示黄色名称。未展开的 `%f`、`%t` 和受保护消息不得被当作有效名称。
- 安装报告中 `other_addons_unchanged` 为 `true`，并保留本次更新前的备份。

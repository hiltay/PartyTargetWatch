# 测试记录

## 环境与范围

- 开发目标：国服正式服 12.1.0；本机客户端安装信息为 12.1.0.69933。
- 本地 Lua 语法和行为测试使用 Lua 5.1（Python Lupa 2.6 的 lua51 运行时）。
- 插件完全独立，仅使用暴雪 API 和界面模板，无第三方运行库。
- 不读取或改写其他插件的 SavedVariables，不注册全局界面钩子，不自动分配或覆盖按键，不修改图形设置、分辨率或 UIParent 缩放。
- 0.2.0 增加用户触发的组队聊天通报和默认关闭的插件焦点通信；没有外部通信服务，也不把收到的焦点或声明存入 SavedVariables。
- 0.3.0 新增多行声明模板、背景不透明度、细分通报拒发提示和 `/ptw status` 本地公开诊断。
- 0.3.0 新增功能尚未在游戏中加载验证；安装文件更新不等于实机通过。模拟测试不能证明真实 secret、taint、服务器送达或限流行为。

## API 依据

- 目标名称和标记的本地显示使用客户端允许的 UI 接口；秘密值不参与拼接、匹配或通信。共享身份只使用确认公开的当前组员全名进行归一化校验。
- 通信锁定不等于普通战斗；活动大秘境可能整段受限。换成普通聊天或外部 HTTP 服务不会把秘密值变为公开焦点，项目不提供这种绕过方式。
- 版本锁定的 API 来源、枚举、限制事件和外部服务结论见 [API-NOTES.md](../docs/API-NOTES.md)。mock 不能代替客户端的受限值与显示行为验证。

## 游戏内验收步骤

1. 启用 PartyTargetWatch 后登录游戏；若新增插件未被识别，退出客户端后重新打开。
2. 单人时应直接看到“队友目标”窗口；选中与清空目标，检查自己的那一行。
3. 组队后请另一名队员切换目标、清空目标，确认对应行随游戏 API 提供的数据变化；检查队员离线、入队、退队。
4. 在战斗中检查名称是否仍能显示，并查看是否产生 PartyTargetWatch 的 Lua 错误。
5. 点击“设置”，调整整体大小和 X/Y 偏移；测试拖动标题、锁定、隐藏、显示、窗口居中。
6. 点击预览应明显标注“示例预览”；结束预览后必须恢复真实单位数据。
7. 执行 `/reload`，检查位置、大小、锁定和隐藏设置保存，示例预览默认结束。
8. 如用于团队，检查 21–40 名成员的双列布局。
9. 检查目标标记设置与取消；逐项切换场景筛选，确认休息区与副本分类、隐藏状态和预览行为。
10. 检查按钮、点击成员行、`/ptw announce` 与用户自行分配的快捷键；在无组队、预览、节流、秘密值和聊天受限情况下应拒发，不把调用成功当作送达确认。
11. 用两台启用共享的客户端验证公开焦点、无焦点、关闭共享、掉线/离组，以及 12 秒过期；进入和离开大秘境等限制时检查旧自动焦点不被当作当前数据显示。
12. 独立启用声明记录，验证默认两条模板接受的中文名、`1`–`8`、`{rt1}`–`{rt8}` 与“取消打断”；确认黄色“约定”、300 秒过期、换场景清理以及自动焦点优先。关闭声明记录后不能继续采用缓存。
13. 从 `/ptw settings` 的“通报格式…”和 `/ptw formats` 打开编辑器。测试 20 条模板、长行换行与光标滚动、中文输入、竖线及 `%mark`/`%text` 的原文保留；有效模板必须按顺序匹配整句，`%text` 不接受空字符串，同模板匹配不同标记时拒绝。
14. 在未保存草稿中测试样本，应仅显示本地测试结果、不发送消息或生成声明；取消编辑不改当前配置。保存有效列表应清空旧声明，保存空列表应停止新记录但仍接受固定“取消打断”；`/reload` 后检查已保存模板。无效模板不能覆盖旧配置。
15. 将背景不透明度设为 `0`、`0.88` 和 `1`，确认仅背景、边框与行底色变化，文字/图标保持；复查滑块、恢复默认、预览与重载保存。
16. 在追随者地下城脱战与战斗时分别运行 `/ptw status`，确认只输出本地公开状态、无真实名称或消息发送；对照按钮拒发提示，记录聊天锁定与目标/成员保密标志，不从脱战状态推断可发送。
17. 如需验证原生手动替代方案，由用户自行创建 `/p 请集火 %t`，选择目标后亲自按下；其 12.1.0 追随者场景效果尚未测试，且宏结果不能作为插件 `SendChatMessage` 权限证明。

范围说明：“当前选中的目标”不等于正在攻击的目标。目标单位不可见、超出客户端可用范围，或游戏限制 API 时，插件不能凭空恢复目标信息。
